### 公開 API

`corpus` は実行時の外部依存を持たず、標準ライブラリで実装する。
モデルは JSON と同じ辞書・配列構造の `TypedDict` とする。
テスト用の牌譜由来データは `packages/corpus/tests/fixtures/` に置く。
文書の JSON 例からコピーしたデータを使用し、テストは `docs/` に依存しない。
牌は `corpus.models.Tile` の `Literal` で 37 種類の表記を列挙する。
手牌・和了牌・副露・ドラ表示牌に同じ型を使い、
実行時の牌表記の検査にもこの定義を使用する。
モデルの型は `corpus.models`、以下の入口は `corpus` から import できる。

| API | 振る舞い |
| --- | --- |
| `ScoringCase` | v1 scoring ケースの型。型注釈自体は実行時の検査を行わない |
| `parse_case(value)` | 型・形式・基本的な整合性を検査し、`ScoringCase` として返す。入力を変更しない |
| `read_cases(path)` | UTF-8 の JSONL を順次読み込み、各ケースを検査して返すイテレータ |
| `write_cases(path, cases)` | 各ケースを再検査して JSONL を出力する。成功時に出力先を置換する |
| `CorpusError` | 不正なデータを表す `ValueError`。`field`、`message`、`path`、`line` を保持する |

パスは `str` または `Path` で指定する。末尾が `.gz` なら gzip を使う。
reader は先読みして全件を検査せず、イテレータを進めた時点で処理する。
途中で処理をやめる場合、呼び出し側はイテレータを `close()` できる。
全件を読まなければ、後続の破損まで検出したことにはならない。

writer は出力先と同じディレクトリに一時ファイルを作成し、
全件の検査・書き込み・クローズが成功してから置換する。
入力ケースが不正、入力イテレータが失敗、書き込みが失敗した場合は
一時ファイルを削除する。親ディレクトリの作成は呼び出し側が行う。
空のファイルは読み書きできるが、検証成功やデータセット完成を意味しない。
存在しないパスやアクセス権などの OS エラーと gzip 自体の破損は、
標準ライブラリの例外として呼び出し側に通知する。

## 初期 v1 の検査方針

- 定義された全フィールドを必須とし、不明値は対応する項目の `null` で
  表す。状況の不明理由の形式は未決のため、今回追加していない。
- 定義外のフィールドは拒否する。`source.scoring_values` の内部は
  出典固有の JSON 値として保持する。
- 整数と真偽値を区別し、未知の版・ケース種別・ルール名は拒否する。
- 副露の牌順は変えず、`chii` の連続性、ポン・槓の同一牌種、
  構成枚数と手牌枚数を確認する。赤と通常の五を合わせて四枚を超える
  手牌も拒否する。暗槓・加槓の未決の鳴き元情報は nullable として保持し、
  意味を確定する検査はまだ行わない。
- 席の範囲とロン・ツモの放銃者指定を確認する。
  ルール固有の行為の合法性や和了状況は再判定・補正しない。
  `renhou` に対するルールの適用も変換器の責務とする。
- 比較除外は初期段階では `expected` 直下のフィールド単位とする。
  未記録の期待値には理由付きの比較除外を必要とする。
  役満時の合計翻が `null` であることは、役満倍率による表現として認める。
- 記録された役の翻・役満倍率の合計と点数の成分を照合する。
  得点計算や役の成立判定は行わず、未定義の役 ID も文字列として保持する。
- イベント全体の点数移動は席数だけを確認し、単独の和了者の収入や
  供託と等しいという検査をしない。複数ロンの意味を保持するためである。
- ID を生成・再構成・マスクしない。呼び出し側が渡した原値を保存する。

## TDD の確認記録

最初の API 未実装による失敗の後、不正な牌・席・手牌枚数・期待値を
受理してしまう失敗を確認し、対応する検査を追加した。
IO では二行目の位置情報不足、後続の不正ケースによる既存ファイルの
破損、gzip 未対応、UTF-8 デコードの先読みによる失敗を確認してから
実装した。テストが通る状態で、型検査と整合性検査の内部構造を整理した。

## 確認結果

- 開発環境の単体テスト: 73 件成功（title 追加後）。
- sdist を生成し、その sdist から wheel を生成できることを確認。
- wheel をインストールした独立環境の Python 3.10.22・3.15.2 で、
  それぞれ全 73 件成功。`site-packages` からの import と、
  実行時依存の宣言が空であることも確認した。
- Ruff の lint・format と ty の型検査が成功。

Python 3.11〜3.14 での全テストと、大規模コーパスの読み込み性能は
今回確認していない。manifest と変換器の実装・結合テストは後続の作業とする。
