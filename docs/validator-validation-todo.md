## 進め方

- 一件ずつ内容を確認し、修正と適切な検証が完了したら、その変更と一緒にチェックを付ける。
- 異なる失敗原因を区別して診断できるようにする。同じ原因や同じ制約を表す条件は、機械的に分割しない。
- 拒否・受理の条件、検証順序、短絡評価が担っていた安全性を維持する。
  原因別にメッセージを分け、例外型とケースの状態分類を維持する。
- テストはメッセージの文言を固定せず、原因ごとの拒否と正常値の受理を確認する。
  既存テストの文言依存は必要に応じて調整する。
- 型検査や値の制約を新設・削除する変更、メソッド分割、周辺の整理は、このリストだけを理由に追加しない。
- 全項目の対応完了後、このファイルと `AGENTS.md` のこのファイルへのリンクを削除する。

## 選択条件：3か所

対象: [selection.py](../packages/validator/src/validator/selection.py) の `Selection.__post_init__()`

[API の契約](validator-results.md) は、`limit` に `None` または正の整数、
`player_count` に `None`・3・4を認め、整数指定としてのboolを認めない。
`case_ids` は空のtuple、または非空文字列を要素とするtupleである。
今回の分割では、この既存の契約と型検査を維持する。
直前に削除した converter の `compress` の型検査とは別に扱う。

- [ ] 01. `limit` の検証
  — 整数型ではない値と、整数だが0以下の値を分ける。
  `None` の許容を維持し、型を先に検証してから大小比較する。
  bool・小数などの拒否、0・負数の拒否、`None`・1の受理を確認する。
  `test_selection.py` の `positive integer` という文言への依存を調整する。
- [ ] 02. `player_count` の検証
  — 整数型ではない値と、整数だが3・4以外の値を分ける。
  `None` の許容を維持する。boolや `3.0` を、整数の3と同一視して受理しない。
  型不正・範囲外の拒否と、`None`・3・4の受理を確認する。
- [ ] 03. `case_ids` の検証
  — 外側がtupleではない状態、要素が文字列ではない状態、要素が空文字列の状態を分ける。
  外側の型を先に検証し、要素は先頭から順に検証する。要素の診断には位置も含める。
  空tuple・通常の文字列・重複IDの許容を維持する。
  空白だけの文字列を拒否する条件や、IDの前後の空白を除去する処理は追加しない。

## ライブラリ結果の正規化：2か所

対象: [adapter.py](../packages/validator/src/validator/adapter.py) の `normalize_result()`

これらのエラーは [validation.py](../packages/validator/src/validator/validation.py) の
`validate_case()` でケースの `error` として保存される。
未対応の `unsupported` や入力不足の `skipped` へ分類を変えない。

- [ ] 04. ライブラリ結果の必須値の欠落
  — `raw.cost`・`raw.han`・`raw.fu`・`raw.yaku` のどれが `None` なのかを区別する。
  現在の順序（cost → han → fu → yaku）で個別に検証し、すべて確認してから後続処理で使用する。
  `raw.error` を先に扱う順序も維持する。
  各値の欠落・複数同時の欠落と、正常な結果を確認する。
  `None` の検証を真偽値判定に変えず、0や空配列の扱いを維持する。
- [ ] 05. 各役の翻の不正
  — 選択した翻が `None` の状態と、数値だが0以下の状態を分ける。
  開いた手では `han_open`、門前では `han_closed` を使う判断を維持する。
  翻の欠落・0・負数の拒否と、正常な通常役・役満の受理を確認する。
  役を特定できる診断を維持し、重複役・未知の役の検証順序も変えない。

## 現状維持とする箇所

- `Selection.matches()` の人数・ID・件数上限は選択条件であり、エラー診断ではない。
- `validation._unsupported_fields()` の共有された複数ロンと、ボーナス付きの後続ロンは、
  個別配分を入力から表せないという同じ理由で比較対象から外しているため、まとめたままとする。
- `compare_result()` の `None` 判定は、値が既知の場合だけ比較を適用する前提条件として維持する。
- `prepare_hand()` の不明な状況は、すでに項目名を列挙して診断しているため分割しない。
- 牌割当の失敗は、対象の牌を示して同じ割当制約の違反を診断しているため分割しない。
- `normalize_result()` の重複役・未知の役は、すでに別の検証とメッセージになっている。
- 出力先の既存ファイル・リンクは、出力先が占有されているという同じ原因としてまとめる。
- CLI の `ValueError`・`OSError` の捕捉は、元の例外のメッセージを保持しており、原因を失っていない。
- ケース状態や終了コードの集計、ドラと抜きドラの合算、計算用の条件式は今回の分割対象に含めない。
