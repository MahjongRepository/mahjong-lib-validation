# validator の実装テストリスト

作成日: 2026-11-03

[validator の設計](validator-design.md) を実装する順序と確認事項を記録する。
全項目は未実装である。[実装・テスト方針](development.md) に従い、
一件を選び Red → Green → Refactor で進める。
このリスト全体を先にテストコードへ変換しない。
実装から得た知見で API・設計・リストを更新する。

## 1. 最初の縦の実装

- [ ] packages/validator の src レイアウト、Python 3.15、workspace 依存を設定する。
- [ ] 単純な四麻の門前ロン一件を corpus から読み、独立した期待値と比較する。
- [ ] 配布名・CLI 名 mahjong-validator、import 名 validator で API と CLI を実行できる。
- [ ] 一致・不一致を返し、API は標準出力・プロセス終了に依存しない。
- [ ] 新規結果ディレクトリに summary.json と cases.jsonl を保存する。

## 2. 入力と変換の境界

- [ ] mahjong の公開 API・依存版・ルール設定を確認して固定する。
- [ ] 手牌・和了牌・副露の牌割当を固定し、赤牌と同種牌の枚数を保つ。
- [ ] チー・ポン・各種槓の種別・開閉・鳴いた牌・相手を正しく渡す。
- [ ] 場風・自風・親・本場・供託・ロン相手を渡す。
- [ ] 三麻の席・ツモ・抜き北とルール設定を渡す。
- [ ] 期待値・出典の役情報を変えても計算入力が変わらない。
- [ ] 必須の和了状況が不明なら false で補完せず skipped にする。
- [ ] 未対応ルール・機能を unsupported とし、対応済み設定で代用しない。
- [ ] 未知の役や解釈できない出力を黙って捨てず error にする。

## 3. 項目比較と診断

- [ ] 役の順序に依存せず、各役の翻・倍率の不一致を検出する。
- [ ] 合計翻・符・役満倍率・点数区分を独立に比較する。
- [ ] 通常役・数え役満・複合役満の翻と倍率を区別する。
- [ ] 素点・本場・供託・収入・親子の支払いを個別に比較する。
- [ ] 複数ロンと責任払いのケースに記録された項目別除外を適用する。
- [ ] 役満の符を一律に除外せず、国士の符は記録された除外に従う。
- [ ] event_score_deltas を単一和了の出力と比較せず未対応として報告する。
- [ ] null・0・空配列、除外・期待値不足・ライブラリ未対応を区別する。
- [ ] 一致・不一致と検証範囲を別々に集計する。
- [ ] ライブラリのエラー返却・例外を計算エラーとして保存し、後続を処理する。
- [ ] 選択ゼロ・全件スキップ・全件未対応を検証成功にしない。
- [ ] 一部ケースの skipped / unsupported も終了コードへ反映する。

## 4. データセット・選択・結果保存

- [ ] manifest 順を保ち、同一 case ID の複数レコードも区別して処理する。
- [ ] 人数・case ID で絞り込んでから件数上限を適用する。
- [ ] 件数上限に達しても全 corpus を検査し、後続の破損・件数不一致を検出する。
- [ ] 全件検査と mahjong の選択範囲を結果で区別する。
- [ ] 全ケース・全結果をメモリへ蓄積せず逐次処理できる。
- [ ] corpus・選択順序・環境・ルール対応表・変換除外の識別情報を保存する。
- [ ] 既存結果を上書きせず、中断・入力不正・書込失敗で完全な結果を公開しない。
- [ ] 正常完了した不一致結果は公開し、終了コード 1 を返す。
- [ ] 引数・corpus・I/O の失敗を終了コード 2 とする。
- [ ] 小さな XML fixture → tenhou-converter → corpus → validator を確認する。
- [ ] wheel をクリーンな Python 3.15 環境へ導入し、未宣言依存を検出する。

ここまでを初期実装とする。以降は各段階へ進む際に具体例・結果スキーマ・
テストリストを詳細化し、一件ずつ実装する。

## 5. benchmark

- [ ] 同じ選択の事前検証が不成立なら計測を開始しない。
- [ ] 読込・入力準備・以前の結果解放を区間外に置き、一括計算だけを計測する。
- [ ] 新規 worker、ウォームアップ、入力再生成とキャッシュ・GC 条件を確認する。
- [ ] 各標本の結果を区間外で検証し、途中の誤り・無効標本も検出する。
- [ ] 生の標本値・中央値・ばらつき・件数を保存する。
- [ ] 制御可能な時計・実行対象で境界と集計を検証し、実時間の速さをテストしない。

## 6. profile

- [ ] sampling と tracing の方式・成果物を明示して実行する。
- [ ] calculation と pipeline の範囲を実証し、準備と事前検証の混入を検出する。
- [ ] Tachyon の収集開始・終了同期と Windows の利用条件を確認する。
- [ ] 未対応条件を明示し、別方式へ黙って切り替えない。
- [ ] 反復時間・回数・入力再利用・標本情報を保存する。
- [ ] profiler を通常の benchmark で起動しない。

## 7. compare

- [ ] 指定した二つの環境で同じ版のツールと期待する mahjong が実行される。
- [ ] 選択順序・設定・Python ビルドの不一致を拒否する。
- [ ] A B / B A の順序で新しい worker を実行する。
- [ ] 両側の検証失敗・無効標本が有効な性能比較にならない。
- [ ] 生の計測値と組ごとの中央値・変化率・範囲を保存し、有意差と混同しない。
