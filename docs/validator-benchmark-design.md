# scoring ベンチマークの設計

準備済みの入力で `HandCalculator.estimate_hand_value` を連続実行する
所要時間を測る。選択した一連のケースを一度ずつ処理した時間を一標本とする。
実装は [validator の実装テストリスト](validator-implementation.md) に従う。

## 入力と事前検証

`benchmark DATASET --limit N --samples K --output OUTPUT` を提供する。
`--limit` は正の整数で必須、`--samples` は正の整数で既定値は 10。
人数とケース ID の絞り込み後に上限を適用し、manifest 順で実行する。
上限到達後もデータセット全体の整合性を検査する。

制御側で選択した全ケースを既存の検証規則で比較する。空選択、不一致、
計算エラー、ケース全体の未対応・スキップがあれば計測を開始しない。
項目単位の比較除外や期待値不足は既存の判定に従い、検証範囲を結果に残す。
各 worker ではコーパスと選択順序の識別情報を照合する。

## 計測手順

標本ごとに新しい Python worker を順次起動する。worker は同じケース順で
一回ウォームアップし、計測用の入力を再生成する。プロセス内キャッシュは
ウォームアップ後の状態を保つ。GC は有効のままとし、明示的に回収する場合は
計測前に行う。

入力を作り、計算 API の参照を準備した後、`perf_counter_ns` でバッチの
開始と終了を一回ずつ記録する。ループ内では準備済みの引数で計算 API を
呼び、戻り値をその場で破棄する。戻り値のリスト生成やレスポンスの検査を
挟まず、入力アダプターと計算 API の引数対応は既存の検証経路と共有する。

| 計測区間 | 処理 |
| --- | --- |
| 区間内 | 入力をたどるループ、引数の受け渡し、計算 API の呼び出し、API 内での戻り値の生成、戻り値の解放 |
| 区間外 | worker 起動、コーパスの読込・解凍・検査、入力生成、ウォームアップ、正規化、期待値比較、集計、出力 |

時計を標本ごとに２回読むことで、ケースごとに時計を読む処理と時計の
分解能が計測値に占める割合を抑える。ループや戻り値の解放は計測値に
含まれる。空ループの時間の差し引きは行わない。

## 失敗と結果

計測中に計算 API が例外を送出した標本は無効とする。ケースを特定できる
情報と失敗理由を診断に保存し、その実行を有効な性能結果として扱わない。
worker の異常終了や選択順序の不一致は実行基盤の失敗とする。
計測中の戻り値は調べないため、その呼び出しでだけ生じた誤答や、
例外を伴わず戻り値に格納されたエラーは検出できない。正確性の記録には
計測前に検証したケースと項目の範囲を示す。

`timings.json` に各標本の経過ナノ秒と状態を記録する。
`summary.json` にケース数、中央値、最小値、最大値、標本標準偏差、中央値に基づく
件数毎秒を記録する。コーパスと選択順序の識別情報、事前検証結果、
ウォームアップ・キャッシュ・GC の条件、Python ビルド、
実際の `mahjong` の版と import 元を保存する。既存の結果ディレクトリを
上書きせず、一時ディレクトリから完了した結果を公開する。
標本が一件の場合、標本標準偏差は `null` とする。

計測境界のテストでは制御可能な時計を使い、バッチの前後で一回ずつ
読み取ることと、選択した入力を順に一回ずつ渡すことを確認する。
実時間の速さはテストの合否に使わない。
