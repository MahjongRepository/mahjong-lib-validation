## fixture の方針

- `packages/tenhou-converter/tests/fixtures/` に小さな XML と
  独立して確認した期待ケースを保存する。
- 単体テストは Git 管理外の `logs/` とネットワークに依存しない。
- 進行のテストでは `INIT` から終局まで必要なイベントを含める。
  `AGARI` だけの抜粋で一発・海底などを復元できたことにしない。
- 実牌譜由来の ID・ユーザー名はマスクし、合成例は `synthetic-` ID にする。
  対局ルール、元イベント位置、加工範囲と期待値の確認方法を記録する。
- 得点の期待値は和了記録を根拠とし、`mahjong` の計算結果で生成しない。
  合成例を実牌譜の符号・精算を確認した証拠として扱わない。
- corpus の既存 fixture は出力モデルの参考にする。
  変換 fixture として使うには、対応する入力 XML の準備と照合を必要とする。

## 初期実装の記録（2026-11-02）

`convert_log` と `convert_files`、`tenhou-converter mjlog` を実装した。
標準ライブラリと corpus だけを使用し、得点計算ライブラリに依存しない。

- `parser.py`: 位置付きの属性検査、XML の版・平坦な構造の検査。
  TreeBuilder で DOCTYPE を拒否し、UTF-16 の宣言も文字列検索をすり抜けない。
- `melds.py` / `rules.py`: 副露の復号と GO の解釈。
  加槓の配列は元ポンの三枚に追加牌を末尾追加し、鳴いた牌の位置を保持する。
- `reconstruction.py`: 四麻・三麻の手番、物理牌の所持、鳴き・抜き北、
  立直、一発、補充ツモ、山の残数とドラを追跡する。
  複数ロンでは状況を維持し、局を閉じるときに本場・供託の総額を照合する。
- `scoring.py`: 役 ID 0〜54 と区分、符、翻・役満倍率、点数の正規化。
  複数人の増減が同じ sc に含まれる場合は、個別の支払い・本場・供託を
  推定せず、理由 `multiple_ron_allocation_unknown` で比較除外する。
- `conversion.py`: 一牌譜の全局を終端まで検査し、ケースをまとめて返す。
  AGARI の副露順が鳴いた時系列と異なる実例に合わせ、照合は内容で行い、
  出力順は AGARI を維持する。
- `sources.py` / `datasets.py` / `cli.py`: ファイル探索・圧縮判定、牌譜ごとの
  集計・診断、corpus の writer による分割と完成ディレクトリの公開。

`report_path` を Python API にも追加した。
診断には `summary_complete` と `dataset_published` を分けて保存する。
`record_count` は変換できたケース数であり、公開失敗時も 0 とは限らない。
引数・探索などの事前検査で処理できない場合は標準例外を通知し、
処理していない入力を変換済みとして報告しない。

### Red → Green → Refactor の記録

最初は convert_log が import できない Red を確認し、四麻の一件を通した。
続いて三麻のドラ ID 未対応、副露と役満の未対応を一件ずつ確認して実装した。
未完局・途中のツモ欠落・流局後の AGARI が成功してしまう Red の後、
手番と所持牌の復元を追加した。

点数では供託以上の収入や 13 翻未満の数え役満が通る問題を再現して修正した。
共有された複数ロンの sc が単独の和了として拒否される Red を確認して、
記録を保持したまま不明な精算成分を除外できるようにした。
ポン直後の加槓が受理される Red も確認し、自己の槓にツモを必要とした。

Green を確認してから、役・点数の抽出、入力探索、バッチ処理、局面復元を分離した。
Ruff・ty を適用し、ケースの型検査は corpus.parse_case に集約した。

### 残る検証範囲

コードは四麻・三麻のファイル変換を提供するが、上の未チェック項目は残る。
とくに全役・大明槓・加槓・抜いた北へのロン・複数ロン・責任払いについて、
実際の天鳳記録で確認する例を増やす必要がある。
和了形や全行為の合法性の判定器としては扱わない。
SQLite と validator への接続は予定どおり別段階である。

### 確認結果

- converter のテストは 58 件成功。
- corpus を含む全体では 238 件成功、実 symlink のテスト 1 件スキップ。
- sdist を生成し、その sdist から wheel を生成できた。
- wheel と corpus をインストールした独立環境の Python 3.10.22・3.15.2 で、
  それぞれ全 238 件成功、同じ 1 件スキップ。
  site-packages からの import、CLI の起動、実行時依存が corpus のみであることを確認した。
- ローカルの四麻・三麻二牌譜を実際の CLI で変換し、17 件を四つの shard に出力。
  corpus.check_dataset で全件・ハッシュ・件数を検査した。

BatchConversionError.report の dataset_published に実際の状態を保持する。
CLI はその診断を標準エラーへ出す。レポート失敗を理由に公開済みの
データセットを削除する処理は行わない。
