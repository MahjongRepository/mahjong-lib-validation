# 天鳳 converter の実装テストリスト

作成日: 2026-11-02

[converter の設計](tenhou-converter-design.md) の確認事項と実装順を記録する。
全項目は未実装。[実装・テスト方針](development.md) に従い、
一件を選び Red → Green → Refactor を進める。
以下を最初からまとめてテストコードに変換しない。
実装からの学びに応じて API・テストリスト・設計を更新する。

## fixture の方針

- `packages/tenhou-converter/tests/fixtures/` に小さな XML と
  独立して確認した期待ケースを保存する。
- 単体テストは Git 管理外の `logs/` とネットワークに依存しない。
- 進行のテストでは `INIT` から終局まで必要なイベントを含める。
  `AGARI` だけの抜粋で一発・海底などを復元できたことにしない。
- 実牌譜由来の ID・ユーザー名はマスクし、合成例は `synthetic-` ID にする。
  対局ルール、元イベント位置、加工範囲と期待値の確認方法を記録する。
- 得点の期待値は和了記録を根拠とし、`mahjong` の計算結果で生成しない。
  合成例を実牌譜の符号・精算を確認した証拠として扱わない。
- corpus の既存 fixture は出力モデルの参考にする。
  変換 fixture として使うには、対応する入力 XML の準備と照合を必要とする。

## 1. 最初の縦の実装

- [ ] 単純な四麻の門前ロン一件を、明示した完全な ScoringCase に変換する。
- [ ] `machi` と同じ物理牌を一枚だけ `hai` から外し、元の牌順を保つ。
- [ ] XML の元子要素位置、原値の log ID、percent encoding した case ID を保存する。
- [ ] `INIT`・GO から場風・局・親・本場・人数・対応ルールを取得する。
- [ ] 役一覧に依存せず、進行から立直と一発を復元する。
- [ ] 記録から符・翻・役・素点・本場・供託・支払いを分離する。
- [ ] `parse_case` を通し、一ファイル入力を `write_dataset` へ接続する。
- [ ] CLI から生成したデータセットを `check_dataset` で全件検査する。

## 2. 入力・構文・集計の境界

- [ ] `.xml` / `.mjlog`、gzip の各拡張子とマジックバイトを扱う。
- [ ] gzip 破損、不正 XML、不正な整数列、必須属性の欠落を位置付きで報告する。
- [ ] DOCTYPE・実体宣言、異なるルート、XML 断片列を拒否する。
- [ ] 未知の版・進行イベントを黙って読み飛ばさない。
- [ ] メタデータの有無でイベント位置を採番し直さない。
- [ ] GO 欠落を既定ルールで補わず、既知の対応外ルールは除外する。
- [ ] `GO.type & 0x010` の非ゼロ／ゼロで三麻・四麻を判定し、他のビットが立っていても人数を取り違えない。
- [ ] 四麻・三麻の混在ディレクトリを変換し、ケースごとの人数を保存する。
- [ ] ディレクトリを相対パス昇順で探索し、非対象ファイルを入力数に数えない。
- [ ] リンク・junction を辿らず、入力内の出力、重複 ID、既存出力を拒否する。
- [ ] 一ファイルの `--log-id` を使え、ディレクトリとの併用を拒否する。
- [ ] 既存出力の拒否前に牌譜の変換を開始しない。
- [ ] 正常な和了なしを converted 一件とし、空データセットは公開しない。
- [ ] 後半で壊れた牌譜から前半のケースを返さない。

## 3. 牌・副露・和了記録

- [ ] 赤五と通常五を区別し、物理牌の重複・範囲外・和了牌の欠落を検出する。
- [ ] チー・ポンの牌スロット順、鳴いた位置、絶対席を確認する。
- [ ] 大明槓・暗槓を区別し、暗槓の鳴き元を null にする。
- [ ] 加槓で元のポンの鳴き元を保ち、元ポンのない加槓を拒否する。
- [ ] チー・ポン・加槓・抜き北・槓の分類ビットを所定の優先順で判定する。
- [ ] `m=41514` は抜き北ビットも立つがポンとして分類する。
- [ ] 赤を含む副露で、牌の取り違えやソートによる位置の破壊を検出する。
- [ ] 進行の副露と AGARI の副露を照合する。
- [ ] ドラ追加、裏ドラのない記録、記録された 0 翻の裏ドラを区別する。
- [ ] 全役 ID の表を独立して照合し、食い下がりは記録された翻を保存する。
- [ ] 未知の役・副露コードを黙って落とさない。
- [ ] 満貫未満〜三倍満、役満・複合役満・数え役満を区別する。
- [ ] 役満の記録符を維持し、国士の符だけを規定どおり比較除外する。
- [ ] 元の全 AGARI 属性と GO 属性を出典へ保持する。

## 4. 和了状況

- [ ] 親ツモ・子ツモ・通常ロンの方法と提供者を進行と照合する。
- [ ] 立直の宣言・成立を分け、宣言牌へのロンで供託を先に増やさない。
- [ ] ダブル立直の最初の打牌と、他家の鳴きによる中断を確認する。
- [ ] 一発のロン・次回ツモ、一発が終了した自己打牌の後を区別する。
- [ ] チー・ポン・暗槓で一発を中断し、加槓・抜き北は和了打診後の中断を反映する。
- [ ] 嶺上ツモ・加槓への槍槓を確認し、最初の加槓への槍槓で一発が維持されることを確認する。
- [ ] 対象ルールで認められない暗槓へのロンを国士無双でも拒否する。
- [ ] 通常の最終ツモ・最終打牌と、槓による残数の変化を確認する。
- [ ] 天和・地和と、鳴きが入った最初のツモを区別する。
- [ ] 役満で通常役が役一覧にない場合も、入力の立直・一発を維持する。
- [ ] 人和は対象ルールに従い false とする。
- [ ] 局間で状態を初期化し、連続 AGARI の途中では初期化しない。
- [ ] 根拠位置を保存し、欠落進行を false や null の多用で成功扱いしない。

## 5. 精算・複数ロン・責任払い

- [ ] 親・子それぞれのロン／ツモを、本場・供託ありでも分解する。
- [ ] `ten` は点単位、`sc` は 100 点単位として解釈する。
- [ ] `base_points` を基本点と取り違えず、素点を記録どおり保存する。
- [ ] ダブロンを元順序で二件にし、各 source の位置と局内和了順を保持する。
- [ ] ダブロンの実記録で各 sc の範囲と本場・供託の受取人を確認する。
- [ ] 三家和了の流局から和了ケースを生成しない。
- [ ] 責任者と放銃者が異なる実記録で支払いと比較除外を確認する。
- [ ] 分離できない成分は null と理由を保存し、既知の他の期待値は維持する。
- [ ] 記録同士の矛盾を比較除外で隠さず、変換失敗にする。

## 6. 三麻・抜き北（初期実装）

- [ ] 三麻でも `seed[0] // 4`・`% 4 + 1` で場・局を取り出し、2 の次の 4 を南一局として読む。
- [ ] 三麻の席を 0〜2 とし、元の四席配列の未使用席の点数・増減・手牌を検査して三席配列にする。
- [ ] 三麻の未使用席での行為や非ゼロの点数を、削除せず不整合として報告する。
- [ ] ポンの相対席は三麻でも `% 4` で絶対席に直し、`who=1, m=27211` を席 0 からの鳴きとする。
- [ ] 二萬〜八萬とチーを受理せず、牌 ID 自体は四麻の体系を維持する。
- [ ] `m & 0x0020` の抜き北を `m >> 8` で復号し、通常の副露へ入れない。
- [ ] 抜いた牌が北かを確認し、同一の北を複数回抜く記録や手牌との重複を拒否する。
- [ ] 進行と AGARI.m の抜き北を照合し、残った通常副露の順序を保持する。
- [ ] `m="31520,31264,30752"` を nuki_count=3・通常副露なしへ変換する。
- [ ] 北の手牌・面子での使用を抜き北と混同しない。
- [ ] 抜き北で一発・地和・ダブル立直の条件が中断されることを確認する。
- [ ] 抜き北の補充ツモ・連続する抜き・槓の順序と、嶺上・海底の判定を確認する。
- [ ] 抜いた北へのロンと提供者を確認し、補充ツモ前の一発・槍槓の扱いを固定する。
- [ ] 抜き北の枚数から期待役を足さず、記録されたドラ翻と独立した入力を保存する。
- [ ] 三麻の親・子ツモで二人分の支払いを保存し、四人目の支払いを補わない。
- [ ] 三麻の本場一本 200 点を含むロンを分解し、四麻の 300 点と混同しない。
- [ ] 追加三麻牌譜由来の小さな fixture で、素点 2000・支払い 700/1300 の子ツモを確認する。

## 7. データセット・CLI・独立利用

- [ ] 複数牌譜で入力数とケース数を区別し、converted + failed + excluded を照合する。
- [ ] 失敗一件につき主原因一件を記録し、後続の入力も診断する。
- [ ] 最後の牌譜が失敗した場合も、完成データセットを公開しない。
- [ ] 全除外・全失敗・全件和了なしを成功終了にしない。
- [ ] 意図的な除外のみがあり、有効ケースが残る場合は集計を付けて公開する。
- [ ] 分割件数・圧縮を指定でき、manifest の件数・順序・ハッシュが一致する。
- [ ] 生成条件・変換器の実際の版を記録し、同じ入力から ID・内容・順序を再現する。
- [ ] 出力 IO 失敗・中断で不完全な完成ディレクトリを残さない。
- [ ] レポートと標準エラーに最終／途中集計と公開状態を示し、終了コードを確認する。
- [ ] 既存レポートを上書きせず、引数不正を変換開始前に検出する。
- [ ] 配布名・CLI 名が `tenhou-converter`、import 名が `tenhou_converter` であることを確認する。
- [ ] Ruff・ty、パッケージのビルド、wheel の独立インストールを確認する。
- [ ] Python 3.10・3.15 の独立環境で実行し、corpus 以外の実行時依存がないことを確認する。

初期実装の完了は上記の四麻・三麻両方の項目を満たした時点とする。
`mahjong` を使う正誤検証までの結合テストは validation の実装時に追加する。
converter の単体・結合テストに検証対象の得点計算依存を持ち込まない。
