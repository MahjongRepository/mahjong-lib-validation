# corpus の整理チェックリスト

## PR の順序と互換性

先にこのパッケージで共通部品を追加し、[天鳳](tenhou-converter.md)と[雀魂](majsoul-converter.md)の各 PR で個別に採用する。[validator](validator.md) は独立して進められる。以下は実装時のチェック項目である。

Python API は変更できる。パッケージ単位でマージできるよう、別パッケージが使用中の API を置き換える場合は呼び出し元の移行時期を合わせる。CLI の引数、既定値、終了コード、出力先と出力形式、および既存の v1 データセットの読み書きは維持する。雀魂のバッチ変換は天鳳の方針に揃え、個別の入力エラー後も走査を続ける。これに伴い、失敗時のレポートには後続入力の件数と診断も含まれる。[現行仕様](../reference.md) · [雀魂の変更計画](majsoul-converter.md)

- [ ] **変換レポートの型と集計を一か所で定義する。** 両コンバーターの `datasets.py` は同じ `Diagnostic`、`Report`、初期カウンターを定義している。`ConversionSummary` と `GeneratorInfo` を既に提供する corpus に変換レポート用モジュールを置く案を推奨する。初期化、理由別の加算、診断の追加、JSON の排他的作成を共通にし、例外の分類・継続判断・stderr の整形は各コマンドに置く。共通部品には XML や protobuf の型を渡さない。
- [ ] **集計の確定時点を守る。** `write_dataset` に渡した `conversion` はケース列挙中に更新される。レポートと manifest が同じ最終値を参照するようにする。途中で失敗する入力列と、除外を含み正常終了する入力列で、最終件数、公開可否、公開時の manifest とレポートの一致を確認する。[データセット実装](../../packages/corpus/src/corpus/datasets.py)
- [ ] **C901 の対象 `_yaku` を「役単位」と「手全体」に分ける。** ID の検査に続いて各役の翻数・役満倍率を検査し、最後に合計を照合している。各役の値の検査を切り出す。通常役の翻数欠落とゼロ、役満への翻数指定、合計不一致を区別し、最初に報告するフィールド（添字を含む）を保つ。抑制を外して Ruff と corpus のケース検証を通す。[対象関数](../../packages/corpus/src/corpus/checks.py) · [ケーステスト](../../packages/corpus/tests/test_cases.py)
- [ ] **索引行の検査を読み込みループから切り出す。** `_read_dataset` の行サイズ、JSON、型、連番ファイル名、件数、ダイジェスト形式の検査を一まとまりにできる。ファイル全体のハッシュ照合、shard の逐次読み込み、総件数照合はストリームの順序に依存する。破損した索引と shard のテストで、エラー位置と件数不一致を検出するタイミングを確認する。[データセットテスト](../../packages/corpus/tests/test_datasets.py)

レポート追加と既存の検証処理の整理は独立した PR に分割できる。
